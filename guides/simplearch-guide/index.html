Introduction & TUI Controls

Booting the official Arch Linux live ISO and mastering the terminal interface.

1. Booting the Arch Live Environment

Boot your machine from an official Arch Linux installation USB flash drive. Once initialized, you will arrive at a root shell prompt with a flashing cursor. Your network is often automatically brought online via DHCP.

archinstall

Type archinstall and press Enter to launch the guided installer.

Figure 1.1: Arch Linux live environment root prompt
Figure 1.2: Archinstall guided TUI main menu

2. Mastering TUI Navigation

The archinstall installer is a curses terminal interface with keyboard-first controls:

  • Arrow Keys or j / k (vim keys): Navigate up and down menus.
  • / (Slash): Opens the interactive fuzzy finder search inside sub-menus.
  • Enter: Selects an option or confirms a dialog.
  • Space: Toggles checkboxes in multi-select menus (Note: Tab does not work here).
  • Esc: Cancels current action or goes back to the parent menu.
STEP 02 OF 10 Est. time: ~1 min

Locales, Mirrors & Multilib

Optimizing package download speeds and enabling 32-bit library support.

1. Regional Mirrors

Keep Archinstall language and Locales as default (en_US.UTF-8). Enter Mirrors and repositories and set your region to your country or a geographically close neighbor. Using local mirrors dramatically reduces package download latency during and after install.

Figure 2.1: Fuzzy-filtering regional mirrors
Figure 2.2: Checking multilib repository

2. Enable the multilib Repository

Under Optional repositories, select multilib. This enables access to 32-bit package libraries on 64-bit Arch.

Why this is critical: Essential tools like Steam, Wine, Proton, and older legacy hardware drivers depend on 32-bit multilib binaries. Turning it on now avoids manual pacman.conf edits later.
STEP 03 OF 10 Est. time: ~3 min

Disk Partitioning, LUKS & Snapshots

Btrfs subvolume layout, whole-disk encryption, and instant snapshot rollback preparation.

1. Partitioning & Btrfs Subvolumes

Select Disk configuration > pick your installation drive > choose Best-effort partitioning > select Btrfs. When prompted for volume structure, select Yes to default subvolumes (@ for root and @home for users).

Turn Use compression to yes (transparent zstd). Do NOT disable copy-on-write (CoW is mandatory for snapshots). Leave LVM disabled.

Figure 3.1: Enabling default Btrfs subvolume structure
Figure 3.2: LUKS applied to root partition (leaving ESP unencrypted)

2. Disk Encryption (LUKS)

Select Disk encryption > choose LUKS > set your encryption password > leave iteration time default (10000ms, or 5000ms if testing in a VM). Under Partitions, select your main Btrfs partition (e.g. /dev/vda2). Leave the EFI system partition (ESP) unencrypted so firmware can boot.

3. Btrfs Snapshots: Snapper

Select Btrfs snapshots > select Snapper. While Timeshift is good, Snapper has the decisive advantage of pairing with limine-snapper-sync, allowing you to boot directly into previous system snapshots from your bootloader if an update ever breaks anything.

Figure 3.3: Snapper active on root filesystem
STEP 04 OF 10 Est. time: ~30 sec

Swap on zram

Configuring compressed in-RAM swap to avoid disk thrashing and lockups.

1. Enable Swap on zram

Select Swap > choose Yes. zram creates a compressed block device in your physical RAM. When memory gets tight, inactive pages are compressed dynamically instead of writing slowly to SSD flash, prolonging drive lifespan and preventing desktop stutter.

Figure 4.1: Enabling zram swap
Figure 4.2: Default zstd algorithm for modern CPUs

2. Compression Algorithm: zstd vs lz4

Modern CPUs (Default): Keep zstd. It provides the best compression ratio with negligible CPU utilization on modern multi-core processors.

Legacy Hardware

If installing on an ancient/weak dual-core (e.g. Pentium E5800), select lz4. It has much lower compression CPU overhead at the cost of a slightly lower compression ratio.

STEP 05 OF 10 Est. time: ~2 min

Bootloader & Plymouth Splash

Choosing between GRUB and Limine, and configuring Plymouth + UKI options.

1. Limine vs GRUB

By default, archinstall pre-selects systemd-boot, which lacks easy snapshot integration. We recommend Limine (or GRUB). Limine provides the cleanest native integration with limine-snapper-sync, perfectly matching Omarchy's instant boot-menu rollback capability.

Recommended Bootloader: Limine
Figure 5.1: Switching from default systemd-boot to Limine
Figure 5.2: Selecting the 'details' theme for boot logging

2. Plymouth: Details Mode

Plymouth handles boot splash graphics. For your initial install, enable it and pick the details theme. This renders kernel log output cleanly through Plymouth so you have immediate visibility if any service hangs during startup. You can switch to an aesthetic graphical theme later with one command.

Legacy Hardware Tip: On old GPUs (e.g. Intel GMA), disable Plymouth completely to prevent black-screen hangs.

Keep Unified Kernel Image (UKI) disabled for now

A Unified Kernel Image bundles the kernel, initramfs, and cmdline into a single signed executable. Limine requires separate kernel and initramfs files to dynamically boot Btrfs snapshot subvolumes (injecting rootflags=subvol=<snapshot>). Enabling UKI here breaks automatic boot-menu rollback entries. Keep it disabled.

STEP 06 OF 10 Est. time: ~1 min

Kernel Selection

Establishing a resilient multi-kernel strategy with automatic fallbacks.

1. Why Install More Than One Kernel?

In archinstall, you can multi-select kernels. Installing linux-lts alongside your primary kernel provides an immediate fallback safety net. If a mainline kernel update ever introduces a hardware regression, you simply select linux-lts from your Limine boot menu to restore a working system.

Recommended Pairing: linux + linux-lts
Figure 6.1: The 4 official Arch kernel options

linux (Mainline)

Tracks upstream Linux closely. Safest default with broadest community testing and latest driver support.

linux-lts (Long Term Support)

Rock-solid stability with backported fixes. Perfect second fallback kernel alongside mainline.

linux-zen

Tuned for desktop multitasking, lower input latency, and gaming responsiveness.

linux-hardened

Security-hardened kernel with exploit mitigations (may conflict with proprietary NVIDIA drivers).

STEP 07 OF 10 Est. time: ~2 min

Hostname & User Security

Disabling root login, creating your sudo user, and setting network identity.

1. Hostname vs Username

Hostname is the machine's name on your network (e.g. elitedesk-800 or arch-desktop). Username is your personal account name. Think of it as username@hostname ("who @ which machine").

Figure 7.1: Setting machine hostname
Figure 7.2: Leave root password blank

2. Disabling Direct Root Login

Leave Root password blank. This disables direct root logins, locking down your system against remote brute-force attacks. All administrative tasks will be executed securely via sudo from your primary user account.

3. Create Your Sudo User Account

Select User account > enter your username and password > toggle sudo to yes. This atomically configures wheel group permissions.

Figure 7.3: Assigning sudo privileges to primary user

Profile Selection: Choose Minimal

Why Minimal is strictly recommended to create a clean foundation for SimpleArch.

1. Profile Types: The Core Distinction

Opening Profile > Type reveals four choices: Desktop, Minimal, Server, and Xorg.

Recommendation: Pick Minimal!
Selecting Desktop installs pre-bundled packages you didn't choose piece-by-piece, and skips custom graphics driver configuration. Picking Minimal gives you a pristine, conflict-free base so SimpleArch's post-install selector can assemble your exact custom stack.

STEP 09 OF 10 Est. time: ~2 min

Audio, Connectivity & Services

Configuring PipeWire, NetworkManager (iwd), UFW firewall, and printing.

1. Audio: Select PipeWire

Under Application, choose PipeWire for audio. PipeWire supersedes PulseAudio and JACK, unifying low-latency audio processing and Wayland screen-sharing protocols.

Figure 9.1: Selecting PipeWire as audio server
Figure 9.2: NetworkManager backend choice

2. NetworkManager Backend: iwd vs Default

Choose Network Manager (iwd backend) if your Wi-Fi card was manufactured after ~2014 (especially Intel chipsets like Wireless 8265/8275). iwd uses kernel cryptography for faster roaming and lower power draw. For pre-2014 hardware, keep the default backend.

Bluetooth = Yes

Enables the bluez daemon and utility tools so wireless peripherals work immediately.

Firewall = UFW

Uncomplicated Firewall is chosen for its simplicity and rock-solid single-machine desktop protection.

Printing = Yes (CUPS)

Enables printing service subsystem, preventing missing print-driver headaches later.

Timezone = Your City

Fuzzy-filter and select your local timezone; keep automatic NTP time sync enabled.

STEP 10 OF 10 Est. time: ~3 to 10 min

Installation & Transition to SimpleArch

Executing the base install, rebooting, and launching SimpleArch.

1. Double-Check and Install

Scroll down the main menu to Install. Press Enter and confirm the prompt by selecting yes. A live countdown will begin, followed by disk formatting and package download. Installation typically takes 3 to 10 minutes.

Figure 10.1: Final installation confirmation
Figure 10.2: Prompt upon completion: select Reboot system

2. Completion: Select "Reboot system"

When installation completes, archinstall prompts: "What would you like to do next?"

Select Reboot system and press Enter. As your machine restarts, remove your USB installation flash drive.
